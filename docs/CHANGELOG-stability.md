# Журнал исправлений по аудиту

Список проблем и план: [AUDIT.md](AUDIT.md). Номера в скобках (#N) ссылаются на таблицы аудита.

## Совместимость и настройка

- **Порт по умолчанию: 8964** (был 8080). Плагин слушает только `127.0.0.1`.
  - Плагин: `settings.port` в `%APPDATA%\Autodesk\Revit\Addins\<год>\revit_mcp_plugin\Commands\commandRegistry.json`.
  - Сервер: переменная окружения `REVIT_MCP_PORT`.
- Переменные окружения сервера:

  | Переменная | По умолчанию | Назначение |
  |-----------|--------------|------------|
  | `REVIT_MCP_HOST` | `127.0.0.1` | адрес плагина |
  | `REVIT_MCP_PORT` | `8964` | порт плагина |
  | `REVIT_MCP_CONNECT_TIMEOUT_MS` | `5000` | таймаут подключения |
  | `REVIT_MCP_TIMEOUT_MS` | `150000` | таймаут ответа (больше максимального таймаута плагина 120 с) |
  | `REVIT_MCP_DB` | `%APPDATA%\mcp-server-for-revit\revit-data.db` | файл SQLite для `store_*`/`query_*` |

- **Протокол:** одно JSON-сообщение на строку (NDJSON). Обе стороны принимают и старый формат без перевода строки, поэтому новый сервер работает со старым плагином и наоборот. Порт при смешивании версий нужно выставить вручную.

## Этапы 0–1. Быстрые исправления и транспорт

**Плагин (`plugin/`)**
- `SocketService` переписан (#1–3, #6, #17):
  - `TcpListener` на `IPAddress.Loopback`, порт из настроек (по умолчанию 8964). Если порт занят, пользователь видит причину в диалоге, а не ложное «Open Server».
  - Чтение потока с `Decoder` (корректный UTF-8 на границах пакетов) и разбор NDJSON без ограничения в 8 КБ. Лимит сообщения 64 МБ.
  - Команды выполняются строго по одной (`SemaphoreSlim`): Revit всё равно обрабатывает их последовательно, а обработчики хранят состояние запроса в полях.
  - Инициализация выполняется один раз за сессию: повторное включение кнопки не регистрирует команды заново. `Stop()` закрывает клиентские соединения.
- `RevitFailureCollector` (#7): на время MCP-запроса подписка на `FailuresProcessing` удаляет предупреждения, а при ошибках откатывает транзакцию без диалога (`SetClearAfterRollback`). Все сообщения возвращаются клиенту в поле `warnings` ответа и пишутся в лог. Вне запроса поведение Revit не меняется.
  - Ограничение: если команда завершилась по таймауту, а транзакция закоммитится позже, её предупреждения покажет стандартный диалог Revit.
- `CommandExecutor` теперь используется (раньше логика дублировалась в `SocketService`): коды `CommandExecutionException` сохраняются, `TargetInvocationException`/`AggregateException` разворачиваются, в лог пишется время выполнения и стек.
- `Logger` (#16): потокобезопасная запись, файл по текущей дате, уровень из `settings.logLevel`, битая строка формата не роняет вызывающий код.
- Удалён неиспользуемый `ExternalEventManager` с фиктивным `ExecuteCommand`. Исправлены сообщения лога «Failed to create command instance» при успехе и строка формата `({1}}`.

**Команды (`commandset/`)**
- Новый базовый класс `Base/McpCommandBase` для всех 24 команд (#4, #6):
  - перед `Raise()` вызывается `PrepareForRaise()` обработчика, поэтому `WaitForCompletion` больше не делает `Reset()` и быстрый результат не теряется;
  - проверяется результат `ExternalEvent.Raise()`: на `Denied`/`TimedOut` возвращается понятная ошибка «закройте диалоги в Revit»;
  - если предыдущий запрос той же команды завершился по таймауту и ещё выполняется в Revit, новый запрос отклоняется (код `-33002`) вместо перезаписи параметров;
  - ошибка, пойманная обработчиком (`LastError`), возвращается клиенту как JSON-RPC ошибка (код `-33003`).
- Все `TaskDialog.Show` с ошибками в обработчиках заменены на `LastError = ex` (#5). Модальное окно осталось только у `say_hello`: это его назначение.
- `delete_element`: id разбираются как `long` (Revit 2024+) без устаревшего `ElementId(int)`, несуществующие id возвращаются в `invalidIds`, а не показываются диалогом.

**Сервер (`server/`)**
- `SocketClient` переписан (#3, #9, #11): постоянное соединение с ленивым подключением и переподключением, NDJSON, сопоставление ответов по `id`, очистка таймеров, немедленный отказ ожидающих запросов при обрыве, понятная ошибка, если Revit не запущен.
- Результат с `success: false` и JSON-RPC ошибки превращаются в `RevitCommandError`. Предупреждения Revit добавляются к результату в поле `revitWarnings`.
- Ветки ошибок всех инструментов возвращают `isError: true` (#13), JSON отдаётся без отступов (#10).
- Удалены пустые `modify_element.ts`, `search_modules.ts`, `use_module.ts`.
- MCP SDK обновлён с 1.7 до 1.32.2, zod до 3.25 (#21). Добавлены `npm test` (встроенный `node:test`) и тесты транспорта и MCP по stdio в `server/test/`. Версия пакета 1.1.0.

**Проверка:** решение собирается для Revit 2020, 2022, 2024, 2025 и 2026 (`dotnet build -c "Release R2x"`, 0 ошибок). Тесты сервера: 11 из 11 (`npm test`): большие сообщения, дробление UTF-8, параллельные ответы, обрыв, таймаут, старый формат, ошибки, предупреждения, переподключение, MCP по stdio.
**Не проверено:** работа внутри запущенного Revit (на машине сборки Revit не запускался).
